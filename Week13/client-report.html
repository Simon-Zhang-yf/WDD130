Client Report

  1. I decided the content and images based on the purpose of the website, which was about traveling to Japan. I chose pictures and information that I thought would be most interesting and useful for people who want to learn about Japan, such as popular places to visit, food, and culture. I also thought about what kind of feeling I wanted the website to give to visitors, so I tried to pick images that looked clean and attractive.
  2. I communicated with my developer mainly through messages, where I explained what content and layout I wanted for the site. There were not many big issues, but sometimes I needed to explain my ideas more clearly so the developer could understand exactly what I wanted. Overall, the communication was smooth and my developer was easy to work with.
  3. Yes, my developer met my expectations. The final website looked professional and included the content and images I wanted. The layout was also easy to use and looked nice on the page.
  4. Next time, I would try to prepare a clearer plan before starting the project, such as a list of all the content and images I want, so the communication process can be faster and easier.

Developer Report

  1. I communicated with my client to confirm the content and the specific position of the images on the website. During this process, I also made some changes to his original design, and I asked for his approval before applying them. There were no big issues, but sometimes it took a little time to make sure we both understood the same idea, since we needed to match his vision with what was possible in the design.
  2. I published the site using GitHub Pages. After I finished each update, I pushed the changes to GitHub and then shared the live link with my client so he could check the progress and give me feedback.
  3. My experience with GitHub was a good learning process. At first, it was a little confusing to understand commits, pushes, and how GitHub Pages worked together. But after practicing several times, I became more comfortable using it to update and manage the website.

General Experience and Reflections

  1. The most challenging part for me was CSS. Sometimes I need to use a colon and sometimes I don't, and it was hard for me to remember all the syntax rules clearly. I often made small mistakes because I forgot a colon or a semicolon, and then the whole style would not work. To overcome this, I practiced writing CSS many times and checked my code carefully when something did not look right. I also looked back at examples from class to remind myself of the correct format. It took time, but I slowly became more comfortable with it.
  2. What I enjoyed most was adjusting the webpage design. It made me happy because in the end, I could get exactly the look that I wanted. Seeing the page change little by little until it matched what I imagined in my mind was a very satisfying feeling.
  3. If I could do this project again, I might try using Vibe Coding to help me build the website. I think it could make the process faster, and I could learn from comparing how it writes code with how I write code myself.
  4. To be honest, I do not feel fully confident yet. I know that Vibe Coding is starting to take away some job opportunities in web development, so this makes me a little worried about my future in this field. However, I plan to keep learning and improving my skills, because I believe that understanding the basics well will still be valuable, even as new tools become more common.
